# n8n-nodes-docker-api — v1.0.0 Implementation Plan

**Status:** approved, not started · **Target:** single 1.0.0 release
**Predecessor:** v0.1.1 (proof of concept — 4 operations, socket + TCP)

---

## 1. Goal

v0.1.1 proved the concept. v1.0.0 makes it the definitive Docker node for n8n:
every capability a Docker user actually needs, implemented properly, with output
you can feed straight into an IF node.

**Positioning is self-standing.** The README sells what this node does and why it
is good. It does not compare against other nodes. Findings about alternatives live
in `docs/internal/` and inform design only.

### The four pillars

| | |
|---|---|
| **No dependencies** | Direct Docker API. No Portainer required — but supported if you have it. |
| **Normalized output** | Stable, flat, predictable. Never raw Docker JSON. |
| **Safe by default** | Read-only credentials, dry run on destructive ops, explicit prune previews. |
| **Complete** | Containers, images, networks, volumes, system — plus events as triggers. |

## 3. Architecture decisions

### 3.1 One client, four transports — VERIFIED

`socket` · `tcp` · `tls` · `portainer`

Portainer was expected to need a second transport. It does not. Verified against a
live Portainer 2.39.5:

```ts
new Docker({
  protocol: 'http', host, port,
  version: `api/endpoints/${endpointId}/docker`,  // prepended verbatim to every path
  headers: { 'X-API-Key': accessToken },
})
```

`listContainers`, `inspect`, `logs` (correctly framed) and `ping` all work.
**Consequence: every operation we write works across all four transports for free.**

> Do NOT try to use docker-modem's `pathPrefix` — path assembly runs
> `url.resolve(base, '/containers/json')`, and an absolute path discards the base
> pathname. `version` is the field that actually prepends.

### 3.2 Binary via n8n binary data

Any operation returning or accepting non-JSON (Container Export, Copy To/From,
Image Build context, Image Load/Save) uses n8n's binary data helpers. Never a
JSON string field — that path irreversibly destroys 27–45 % of a real archive.

### 3.3 Every operation terminates

No operation may stream indefinitely. Bounded one-shot by default; anything
genuinely event-shaped belongs in the Trigger node.

### 3.4 Normalization is the contract

One normalizer per resource type, shared by every code path that returns it.
The v0.1.1 bug where `list` and `start`/`stop` returned different shapes for the
same container must be structurally impossible — normalize from a single source
of truth, not per-operation.

### 3.5 Silence is a bug

Any path that can return "nothing" must distinguish *no data* from *could not read
the data*. This is the root cause of both our TTY bug and their Archive Info bug.

## 4. Credentials

Current schema has real gaps. All must be fixed:

| Change | Why |
|---|---|
| Add `portainer` to `authMode` + Server URL, Access Token, Endpoint ID | strict superset; Endpoint ID via `loadOptions` dropdown |
| **Implement TLS** | schema exists since 0.1.0, never implemented |
| **Add `required: true`** to conditionally-required fields | today `getSchema` reports `required: []` — a TCP credential saves with an empty host |
| **Add `credentialTest`** (`docker.ping()`) | today there is no Test Connection button at all; a bad credential fails only at run time |
| **Add credential `icon`** | renders as a grey `?` in the credentials list |
| Platform-aware `socketPath` default | `/var/run/docker.sock` never works on Windows; needs `//./pipe/docker_engine` |
| Extend `accessMode` enforcement | new write ops (`create`, `run`, `exec`, `copyTo`, `build`, `push`, `prune`, …) must be in the guard list |

## 6. New capabilities

### Run Container (ephemeral)
create → start → wait → capture logs → auto-remove, as **one** operation.
Returns `{exitCode, logs, durationMs, containerId}`. Must clean up on failure —
a workflow that errors midway must not leak containers. This is the
AI-sandbox / "run this script in isolation" use case.

### Wait For Container State
Target `running` | `healthy` | `exited`, with timeout. Docker's `/wait` only waits
for *exit*; waiting for *healthy* requires polling `inspect` and reading
`State.Health.Status`. Today that is a manual loop + IF node. This is the missing
piece of every deploy-then-verify workflow.

### Execute Command
Unified exec: create + start + inspect in one operation.
Returns `{stdout, stderr, exitCode, durationMs}`. Output is multiplexed and must
reuse the log demuxer — **including the TTY branch**.

### Copy To / From Container
n8n binary data in and out. Docker's archive endpoints are tar; we tar/untar so the
user deals in files. Covers config injection, artifact extraction, backups.

### Normalized Stats
Docker returns cumulative counters. Return `cpuPercent`, `memoryUsageMB`,
`memoryLimitMB`, `memoryPercent`, `networkRxMB`, `networkTxMB`, `pids`.
CPU % needs the delta between `cpu_stats` and `precpu_stats` — both are present in
a single one-shot response, so no second call is needed.

### Pull Image with completion
`/images/create` streams newline-delimited progress JSON. Consume to completion,
return a clean final status. Never hang, never return progress soup.

## 7. Docker Trigger node

Separate node type (`DockerTrigger`) — n8n requires triggers to be their own node.

**Events:** container `start`, `die`, `stop`, `kill`, `oom`, `health_status`;
image `pull`, `delete`; volume and network lifecycle.

**Filters** pushed to Docker's own `filters` query param — by container name,
label, image, event type. Do not stream everything and discard client-side.

**Two hard requirements:**

1. **Catch-up.** Persist the last-seen event timestamp; reconnect with
   `since=<that>`. Without it, every event during an n8n restart is lost — the
   difference between a trigger and a trigger you would page on.
2. **Reconnection.** `/events` is long-lived and dies on daemon restarts, socket
   hiccups, and Docker Desktop sleeping. Needs backoff + resume.

## 8. Breaking changes (approved)

v0.1.1 → v1.0.0 is intentionally breaking. ~28 downloads/month; a compatibility
layer is not worth its cost.

| Change | Reason |
|---|---|
| `ports` populated on start/stop | was always `[]` — read from `NetworkSettings.Ports` on the inspect path |
| `createdAt` always ISO with ms | inspect path leaked Docker's raw nanosecond string |
| `labels` respects `includeLabels` everywhere | start/stop ignored the flag |
| Consistent shape across all operations | the same container must not have two shapes |

Document all of these in CHANGELOG under a **BREAKING** heading.

One release, but built in dependency order. Each phase ships with tests before the
next begins.

| Phase | Content |
|---|---|
| **1. Foundation** | 4-transport client, credential rework (TLS, portainer, required, test, icon), normalizer v2 (single source of truth), error handler pass, access guard extension |

| **3. Image** | all 10 |
| **4. Network / Volume / System** | all 17 |
| **5. New capabilities** | Run, Wait For State, Execute Command, Copy To/From, normalized Stats, Pull with completion, prune previews |
| **6. Docker Trigger** | events, filters, catch-up, reconnection |
| **7. Custom API Call** | escape hatch |
| **8. Polish** | README rewrite, docs, credential icon, UI/UX pass over every operation panel |

Phase 1 is load-bearing — everything else depends on the transport abstraction and
the normalizer being right. Do not rush it.

## 10. Test strategy

Three layers, all already standing (see `DEVELOPMENT.md`):

1. **Unit** (`npm test`) — parsers, normalizers, guards. Fast, no Docker.
   *Gap to close:* still no `test/integration/`. Add dockerode-level integration
   tests so logic regressions are caught in seconds rather than via a full n8n round trip.
2. **End-to-end through n8n** (`run-test.js`) — every operation gets a spec.
   Assert on execution `runData`, never the webhook response body.
3. **UI/UX** (`agent-browser`) — verify `displayOptions` show/hide per operation.
   This breaks silently as fields are added, and 48 operations is a lot of fields.

### Rules

- **Every operation ships with a harness spec.** No exceptions.
- **Every bug fixed ships with a regression test naming the cause.**
- **Fixture safety is absolute** — state-changing operations only ever touch
  `n8ntest-*`. Extend `DESTRUCTIVE_VERBS` in the same commit that adds a new
  mutating operation, and build synthetic fixtures rather than reusing real images.
- **Add `npm test` to CI** — already added to `prepublishOnly`.
- Keep the comparison rig for features where "better" is a claim worth measuring.

### New fixtures needed

Beyond the current `n8ntest-*` set: an image to tag/push/remove, a network, a
volume, a container with a **healthcheck** (for Wait For State), and a
multi-file path for Copy To/From.
